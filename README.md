# مهمتنا — إعداد الموقع للمبتدئين

الموقع ده واجهة عربية RTL، والبيانات الفعلية بتتحفظ في Supabase. GitHub Pages بيستضيف ملفات الموقع فقط؛ تسجيل الدخول وقاعدة البيانات ورفع الملفات من Supabase.

## ملفات المشروع
- `index.html`: واجهة الموقع.
- `supabase-schema.sql`: الجداول وسياسات الحماية وتخزين الملفات.
- لا ترفع أبدًا `service_role` key أو كلمة سر قاعدة البيانات إلى GitHub.

## الخطوة 1: إنشاء مشروع Supabase
1. افتح https://supabase.com/ وسجّل حسابًا.
2. أنشئ مشروعًا جديدًا باسم مثل `mahmotna-group`، واختر كلمة سر قوية لقاعدة البيانات واحفظها عندك.
3. انتظر حتى يكتمل إنشاء المشروع.
4. من إعدادات المشروع/Connect أو Project Settings > API، انسخ **Project URL** و**publishable/anon key**. استخدم المفتاح العام publishable (أو anon القديم). لا تستخدم `service_role` أو `secret key` في المتصفح.

## الخطوة 2: إنشاء الجداول وسياسات الأمان
1. من لوحة Supabase افتح **SQL Editor** ثم **New query**.
2. افتح ملف `supabase-schema.sql` من المشروع، وانسخ كل محتواه إلى المحرر.
3. اضغط **Run**. لو ظهر خطأ، اقرأه ولا تكمل قبل إصلاحه.
4. السكربت يجهّز جداول profiles/tasks/submissions وسياسات RLS وbucket خاص بالملفات. قاعدة البيانات هي التي تمنع العضو من تعديل التاسكات، مش مجرد إخفاء الأزرار.

## الخطوة 3: ربط صفحة الموقع بمشروع Supabase
1. افتح `index.html` بأي محرر نصوص.
2. ابحث عن السطرين:
   `const SUPABASE_URL = "PASTE_SUPABASE_PROJECT_URL_HERE";`
   `const SUPABASE_ANON_KEY = "PASTE_SUPABASE_ANON_KEY_HERE";`
3. ضع Project URL والمفتاح العام مكان النصين بين علامتي الاقتباس. لا تضع `service_role` key أبدًا.
4. احفظ الملف.

## الخطوة 4: نشر الموقع على GitHub Pages
1. أنشئ Repository جديدًا على https://github.com/ (ممكن تسميه `mahmotna`).
2. ارفع `index.html` إلى جذر المستودع، وليس داخل مجلد فرعي. لا يلزم رفع ملف SQL بعد تنفيذ الإعداد، لكن احتفظ به عندك.
3. افتح **Settings > Pages**.
4. في **Build and deployment** اختار **Deploy from a branch**، ثم `main` و`/(root)`، وبعدها **Save**.
5. انتظر دقيقة أو اثنتين، وسيظهر رابط الموقع في صفحة Pages. افتحه واختبر تسجيل الحساب وتسجيل الدخول.

## الخطوة 5: إعداد تسجيل الدخول
1. في Supabase افتح **Authentication > URL Configuration**.
2. أضف رابط GitHub Pages الظاهر عندك إلى **Site URL** و**Redirect URLs**. إذا كنت تستخدم رابطًا من نوع `https://USERNAME.github.io/mahmotna/` أضف هذا الرابط كما هو.
3. من **Authentication > Providers > Email** راجع إعداد تأكيد البريد. الأفضل ترك تأكيد البريد مفعّلًا؛ المستخدم يؤكد بريده قبل تسجيل الدخول.
4. جرّب إنشاء حساب عضو ببريدك أولًا. لو تأكيد البريد مفعّل، افتح رسالة التأكيد.

## الخطوة 6: ترقية حسابك وحساب المسؤولين
1. بعد إنشاء الحساب، افتح **SQL Editor** في Supabase.
2. نفّذ الاستعلام التالي وحده بعد تغيير الإيميل:
   ```sql
   update public.profiles p
   set role = 'admin'
   from auth.users u
   where p.id = u.id and u.email = 'YOUR_EMAIL@example.com';
   ```
3. كرر ذلك لكل مسؤول موثوق. لا تجعل حسابات الأعضاء مسؤولين.
4. سجّل خروجًا ثم دخولًا مرة أخرى في الموقع لتظهر لوحة المسؤولين.
5. باقي الحسابات تبدأ تلقائيًا بدور `member`. لا توجد صفحة عامة ترفع صلاحيات المستخدم.

## استخدام الموقع
- المسؤول: يضيف التاسك ويحدد موعدها وطريقة التسليم (ملف/لينك/الاتنين)، يعدّلها أو ينقلها للأرشيف، ويراجع التسليمات.
- العضو: يشوف التاسكات، يفتح التفاصيل، يرفع ملفًا حتى 15MB أو يضع رابطًا حسب إعداد التاسك، ويرى حالة التسليم وملاحظات المسؤول.
- الملفات محفوظة في Storage خاص، وروابط التحميل الموقعة قصيرة المدة.
- فلتر «الأرشيف» يعرض التاسكات التي وضع المسؤول حالتها «مكتملة».
- جرّب أولًا بحساب مسؤول وحساب عضو تجريبيين قبل نشر الرابط للمجموعة.

## ملاحظات مهمة
- المفتاح العام (publishable/anon) مصمم للاستخدام في الواجهة فقط مع RLS مضبوط. لا تضع مفتاح `service_role` أو أي secret key في HTML أو GitHub.
- أي شخص يستطيع إنشاء حساب عضو إذا كان التسجيل العام مفتوحًا. لو عايز تمنع التسجيل المفتوح، عدّل إعدادات Auth أو خلّي المسؤولين ينشئوا الحسابات من لوحة آمنة لاحقًا.
- حاليًا الصفحة تعرض التاسكات للزوار أيضًا، لكن التسليم يتطلب تسجيل الدخول. لو تفضّل أن الأعضاء المسجلين فقط يشوفوا التاسكات، عدّل سياسة القراءة قبل الإطلاق.
- لا تستخدم بيانات حقيقية أو ملفات حساسة في الاختبار الأول.
- الخطوة التالية المقترحة للإنتاج: تفعيل إشعارات البريد، إضافة صفحة إدارة أعضاء، وسجل تدقيق لتغييرات المسؤولين.
